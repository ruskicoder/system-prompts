# installers

## Purpose
Copy the generated integrations into each tool's per-user configuration or into one project, and add opt-in packs per set.

## Responsibilities
- `install/spec.json` lists the tools, their target folders per OS (locations `HOME`, `DATA_HOME`, `CODEX_HOME`, `OPENCODE`), the core steps per tool, the project installs, and the harness options.
- `tools/generate_installers.py` reads the spec and `packs/*/pack.json`, validates the packs, and writes `install/install.sh`, `install/install.ps1` and `install/install.cmd` with a "Generated by" header. `--check` exits 1 when a committed installer is stale. `--packs-dir`, `--out` and `--source-root` serve the tests.
- `tools/installer/runtime.sh` and `tools/installer/runtime.ps1` hold the installer logic. The generator prepends a data block built from the spec and the packs.
- Core step operations: `tree` (copy a folder), `file` (copy one file), `doc` (copy a document and keep a harness block in the destination), `block` (append the `prompt-orchestrator` marker block to `~/.claude/CLAUDE.md`), `attribution` (run `ensure_attribution_off.py` and record what it creates), `plugin` (Antigravity package, checked against `.agents/skills/` first).
- Pack modes: in mode `mcp` (the default), the skill folders go to `<data_home>/skills-mcp/<pack>/`, `pack_helper.mjs skills-index` builds `<data_home>/skills-mcp/index.json`, and `install/po_skills_server.mjs` runs as the `po-skills` MCP server with the tools `search_skills`, `load_skill` and `list_packs`. The installer registers `po-skills` once per selected tool through the tool's `mcp` entry in the spec. In mode `skills`, the skill folders go into the pack skills folder of each selected tool. Without `--mode`, an installed set keeps its mode.
- Pack kinds: `skills` copies each skill folder in the set's mode, `package` also copies `package/` to `<data_home>/packages/<pack-id>/`, and `release` (procable) downloads or reads a release bundle, verifies it against the lock and runs the engine. In mode skills, the engine installs at user scope and the installer records the files the engine created. In mode mcp, the engine runs in a temporary home, the installer copies the skill folder to `<data_home>/skills-mcp`, and the hook groups move to the real hook files with the skills-mcp launcher.
- The manifest `<data_home>/install-manifest.tsv` records owner, kind, path, hash and extra per file. Owners are `core:<tool>`, `harness:<tool>`, `pack:<pack>:<set>:<tool>`, `pack:<pack>:<set>:mcp`, `pack:<pack>:payload`, `po-skills`, `po-skills:<tool>`, `project:<dir>`, `windsurf:<dir>` and `@dirs` for created folders. Removal deletes a file only when its hash matches, restores backed-up files, strips marker blocks and hook entries, and removes created folders once they are empty.
- `packs/README.md` describes pack format v1, with `release` as an optional third kind.
- `tools/validate_packs.py` checks pack format v1: schema keys, the id, sets (each skill folder in exactly one set), front matter (name, description of at most 1024 characters, third-party fields), the payload for kind `package`, the lock for kind `release`, LICENSE, and name clashes with the core. The validator also checks the description forms that the `po-skills` index reads and rejects a pack server named `po-skills`.
- `install/antigravity_plugin.py` keeps `validate_package()`, which `skills/validate_skills.py` runs.
- `install/systemd/prompt-orchestrator.service` is a sample user unit and no installer uses it.
